# 0004 · resx 标题留空 ≠ 隐藏该组

- **状态**：✅ 已确认（实机）
- **日期**：2026-10-20
- **相关**：[../architecture/overview.md](../architecture/overview.md)

## 背景

Emby 的 GenericEdit 里，嵌套的 `EditableOptionsBase` 属性会渲染成一个**折叠组**，组标题取父属性的
`DisplayName`（也就是 `[DisplayNameL("...")]` 指向的资源键）。

直觉上，把那个资源键的值改成空字符串，应该就不显示标题了 —— 于是可以用它来"省略"一层嵌套。

## 决策

**不要用空字符串省略标题。要真的去掉标题，必须把那层容器拆掉（把字段提到上一层）。**

## 理由

实机验证：resx 值为空串时，页面上会出现一个**没有标题的折叠块** —— 一块缩进区域，用户不知道它是什么。
比多一个标题更糟。

当时「基础设置」页有两个这样的块：`GeneralOptions_EditorTitle_General_Options` 和
`ModOptions_Group_ChineseSearch`，都是空串。

## 后果

- 拍平 `GeneralOptions` / `ModOptions` 两层容器：`TaskConcurrency` / `Memory` / `ChineseSearch`
  提到 `PluginOptions` 顶层，旧容器留 `[Browsable(false)]` + **无初始化器**（JSON 没有该节点时保持 null，
  据此判断是否需要迁移），在 `Plugin.Initialize` 里一次性把值提上来并落盘。
- 代价：约 90 处引用改动 + 15 个字段的迁移。
- **品牌版本行是反例**：把它提到顶层虽然去掉了组的缩进问题，但视觉效果更差，已回滚
  （`8a29378`）。**"提到顶层"不等于"更好看"，涉及视觉的改动必须先看效果再落码。**

## 通用规则

给嵌套 `EditableOptionsBase` 补标题时，别用空串"省略"。要么给个真标题，要么把那层拆掉。
