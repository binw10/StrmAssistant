## 一、目标与验收口径

Wiki「提取 ISO 媒体信息」第 3 条原文：**检测双层杜比 P7 原盘、显示增强层**。

验收标准（对齐 PRO 可观测行为）：
1. 双层 DV 原盘（BL 4K + EL 1080p）的条目，其**增强层**媒体流被标注为 Dolby Vision Profile 7。
2. Emby 条目媒体信息 / 多版本徽标能显示该标注（PRO 侧的呈现文案为 `DV P7`，另有 `DV P5/P8/P9`）。
3. 非双层 DV 的普通条目**行为完全不变**（零副作用）。

## 二、代码级证据：PRO 到底怎么做的（推翻 v8 旧假设）

### 2.1 v8 / v6 的旧判断（**错误**）

- v8 第 3 阶段写：「复用第 1 阶段的自定义 ffprobe 基建」。
- v6 L2-2 写：「通过自定义 ffprobe 探测 `dv_bl_signal_compatibility_id` / 增强层流」，并标注「**需自定义 ffprobe**」。

### 2.2 反编译实证（`_pro_tmp/decompiled_v2/A----------\A----------.cs:60063-60245`）

PRO 的真实实现是一个**纯媒体流几何 + 色彩启发式**方法（入参 `MediaInfo`，可强转为 `MediaSourceInfo`），其控制流还原后为：

```csharp
// 1) 取视频流，按 像素面积 降序 Top2
list = mediaStreams
         .Where(s => s.Type == Video && s.Width > 0 && s.Height > 0)   // Type==2
         .OrderByDescending(s => (long)s.Width * s.Height)
         .Take(2).ToList();

if (list.Count != 2) return;   // 取前二；实际门槛为「≥2 条视频流」，多出的流不参与判定
val  = list[0];                       // 面积大者 = 基础层 BL（4K）
val2 = list[1];                       // 面积小者 = 增强层 EL（1080p）

// 2) 两条流都必须是 hevc
if (!string.Equals(val.Codec,  "hevc", OrdinalIgnoreCase)) return;
if (!string.Equals(val2.Codec, "hevc", OrdinalIgnoreCase)) return;

// 3) 基础层必须是 HDR10（ExtendedVideoType == 100）
if ((int)val.ExtendedVideoType != 100) return;

// 4) 分辨率严格 2 倍关系（宽比与高比各 ≈2.0，容差 0.1）
if (Math.Abs(val.Width  / (double)val2.Width  - 2.0) > 0.1) return;
if (Math.Abs(val.Height / (double)val2.Height - 2.0) > 0.1) return;

// 5) 标注增强层
val2.ExtendedVideoType    = (ExtendedVideoTypes)130;      // DolbyVision
val2.ExtendedVideoSubType = (ExtendedVideoSubTypes)13076; // DoviProfile76
```

**三点关键结论**：

| 结论 | 依据 |
|---|---|
| **PRO 不依赖自定义 ffprobe、不解析 DOVI side data / `dv_bl_signal_compatibility_id`** | 函数内无任何外部进程调用、无 ffprobe 输出解析，只读 `MediaStream` 已有字段 |
| **判定条件 = 2 条 HEVC 视频流 + 面积 2:1 + BL 为 HDR10** | 上述控制流逐条还原 |
| **PRO 标注的是「增强层」而非基础层**（`val2` = 面积较小者） | `case 2` 写入目标是 `val2`；与 Wiki「显示增强层」一致 |

**收益**：社区版**无需引入任何 ffprobe 能力位依赖**即可对齐本项能力（`FfmpegPathOverride.ProbeSupportsBluray` 与本项无耦合）。

### 2.3 与第 1 阶段实测的吻合度（我们的样本天然满足全部前置条件）

P1-4 实测（`docs/P1-4-ISO真碟回归测试-诊断记录.md` §7.5）：

| 前置条件 | 样本 253 / 424 实测值 |
|---|---|
| 恰好 2 条视频流 | ✅ 2 流（`hevc 3840x2160` + `hevc 1920x1080`）|
| 均为 hevc | ✅ |
| BL 为 HDR10 | ✅ `smpte2084/bt2020`（Emby 归一化为 Hdr10=100） |
| 宽/高各 2 倍 | ✅ 3840/1920 = 2.0；2160/1080 = 2.0 |

→ **本项一旦落地，样本应立即命中**（当前样本探测已出 2 流，但无任何 DV 标注）。

## 三、Emby 侧事实（本机 4.10.1.0 反射实证）

| 项 | 实测结论 |
|---|---|
| `ExtendedVideoTypes` | `None=0, Hdr10=100, Hdr10Plus=110, HyperLogGamma=120, **DolbyVision=130**` |
| `ExtendedVideoSubTypes` | `DoviProfile02=13002, DoviProfile10=13010, …, **DoviProfile76=13076**, DoviProfile81~85, DoviProfile92` |
| `MediaStream.ExtendedVideoType` | **可写**（CanWrite = True） |
| `MediaStream.ExtendedVideoSubType` | **可写**（CanWrite = True） |
| `MediaStream.VideoRange` / `ExtendedVideoSubTypeDescription` | **只读**（CanWrite = False）→ 与 PRO 只写前两个字段一致 |
| `MediaProbeManager.GetMediaInfoInternal` | `Task<MediaSourceInfo> GetMediaInfoInternal(MediaSourceInfo, string inputPath, string primaryPath, MediaProtocol, bool, bool, CancellationToken)` → 返回 **Task**，不适合直接 Postfix 取值 |
| **`ProbeResultNormalizer.GetMediaInfo`** | `MediaInfo GetMediaInfo(ProbeResult, bool isAudio, string path, MediaProtocol)`，`MediaInfo : MediaSourceInfo` → **返回已归一化的实体，是唯一自然挂点** |

### 3.1 社区版现成挂点（重大便利）

`StrmAssistant/Mod/ExclusiveExtract.cs` **已经**给 `ProbeResultNormalizer.GetMediaInfo` 挂了 Postfix：

```csharp
_getMediaInfo = probeResultNormalizer.GetMethod("GetMediaInfo", BindingFlags.Instance | BindingFlags.Public);
PatchUnpatch(PatchTracker, true, _getMediaInfo, postfix: nameof(GetMediaInfoPostfix));

[HarmonyPostfix]
private static void GetMediaInfoPostfix(ProbeResult data, bool isAudio, string path,
    MediaProtocol protocol, MediaInfo __result) { … }
```

这**正是 PRO 的 MonoMod 补丁所在的同一位置**——社区只需在同一方法上再加一个 Postfix（或把逻辑并入），即可拿到 `MediaInfo __result` 并写 `MediaStreams`。

### 9.2 相对方案的 3 处实现偏差（含理由）

1. **判定门槛表述修正**：PRO 实际是「≥2 条视频流，按像素面积取前二」，不是「恰好 2 条」。实现与文档 §2.2 已同步更正（多出的流如画中画/花絮轨不参与判定）。
2. **未命中日志降级为 `Debug`**：方案原写「命中/未命中均 Info」。若未命中也打 Info，每次 ffprobe 都会刷一条日志（普通片源全都不命中），故改为仅 `DebugMode` 输出原因。
3. **DV-3 改为扫描全部视频流取最优档位**：因标注落在**增强层**（1080p EL），而 `GetSources` 原先只看第一条视频流（基础层 HDR10），只改主视频流会漏掉 DV 信息。同时新增 DV 细分评分档 `P7=520 / P8=515 / P9=510 / P5=505 / DV=500`，JS `hdrs` 列表按同序扩展以保证前后端排序一致。

### 9.3 关键实现依据（编译期实证）

`mediabrowser.server.core 4.9.1.90` 参考包内已确认：`ExtendedVideoTypes.DolbyVision = 130`、`ExtendedVideoSubTypes.DoviProfile76 = 13076`（且 `DoviProfile81~85 / 92 / 50` 齐备），`MediaStream.ExtendedVideoType / ExtendedVideoSubType` **可写**，`VideoRange / ExtendedVideoSubTypeDescription` **只读**。→ 无需反射兜底，直接编译期引用，4.9 与 4.10 通用。
