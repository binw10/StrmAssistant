## 一、P0：分词器写路径缺失 —— **唯一必修的 bug**

### 1.1 症状（实测复现，不是推测）

```
11:07:29.123 Error SqliteItemRepository: Error saving items
  SQLitePCL.pretty.SQLiteException: Error: no such tokenizer: simple
     at SqliteItemRepository.SaveSearchRows(...)
     at SqliteItemRepository.SaveItemsInTranscation(IDatabaseConnection db, ...)
     at SqliteItemRepository.SaveItems(...)
11:07:29.174 Error ProviderManager: Error refreshing item 原盘 428 ...
```

**影响面比"搜索坏了"严重得多**：`SaveItems` 的**整个事务回滚** → **任何条目的元数据写入都会失败**（刷新、刮削、打标签全挂）。而且只在特定库（用了 `simple` 分词器的 `library.db`）出现，用户很难自己定位。

**触发条件**：`EnhanceChineseSearch` 曾经开启过（`fts_search9` 已用 `tokenize="simple"`），之后任何一次元数据写入。

### 1.2 已排除的假设

| 假设 | 排除证据 |
|---|---|
| PR #1 没合入 | 已在 `6b29c60`（PR #1 的 merge commit） |
| 选项关闭导致不加载 | PR #1 已把 `PatchPhase1()` 改成**无条件**调用；实测**选项开启、补丁全绿时照样报错** |
| `CreateConnection` patch 打错重载 | `[TokDbg]` 实测 postfix 确实命中 `repo=SqliteItemRepository` |
| `LoadTokenizerExtension` 加载失败 | 实测 `probe=False → Load OK hash=61156281`，加载**成功** |
| 探针假阳性 | 加载成功的那个连接后续 `probe=True` 是正常的；问题连接**根本没进 postfix** |

### 1.3 根因（高置信度）

Emby 4.10.1.0 `Emby.Sqlite.BaseSqliteRepository`（`/tmp/bsr.cs:114-126`）三个重载全是一行转发：

```csharp
protected IDatabaseConnection CreateConnection()                          => CreateConnection(isReadOnly: false);
protected IDatabaseConnection CreateConnection(bool isReadOnly)           => CreateConnection(isReadOnly, CancellationToken.None);
protected IDatabaseConnection CreateConnection(bool isReadOnly, CancellationToken ct)
                                                                          => ConnectionManager.CreateConnection(isReadOnly, ct);
```

插件只 patch 了**第三个**（PR #1 的选择）。但前两个是**一行方法，极易被 JIT 内联** —— 一旦内联，调用点直接跳到 `ConnectionManager.CreateConnection(...)`，**Harmony detour 被绕过**。

**实测佐证**：`SaveItems`（用无参重载）那次调用**完全没有 postfix 日志**；而直接调用 2 参重载的读路径（`CreateConnection(isReadOnly: true, ct)`）每次都正常触发。

### 1.4 修法：改 patch 虚方法（唯一出口 + 无法内联）

**目标**：`Emby.Sqlite.PooledDatabaseConnectionManager.CreateConnection(bool isReadOnly, CancellationToken cancellationToken)`

**为什么是它**：
- `public override` → **虚调用无法内联**，detour 一定生效
- 它是**所有连接（读+写）的唯一出口**，不再依赖"哪个重载被调用"
- 不依赖 `BaseSqliteRepository` 的重载数量 → **跨 Emby 版本更抗变**

**改动落点**：`StrmAssistant/Mod/EnhanceChineseSearch.cs`
1. `OnInitialize` 里新增反射：加载 `Emby.Sqlite.dll` → `Emby.Sqlite.PooledDatabaseConnectionManager` → `GetMethod("CreateConnection", [bool, CancellationToken])`
2. `PatchPhase1` 里改为 patch 这个虚方法（可保留原有 `BaseSqliteRepository` 的 patch 作为双保险）
3. `CreateConnectionPostfix` 签名不变（`object __instance, ref IDatabaseConnection __result`），但 `__instance` 会变成 `PooledDatabaseConnectionManager` → **`_dbFilePath` 反射会拿不到路径**，需要改成"manager 无法判断库名 → 一律加载"（幂等，代价可忽略）

**验收**：
1. 启动后 `EnhanceChineseSearch - Load Success (search patches active)`
2. `POST /emby/Items/428/Refresh?metadataRefreshMode=FullRefresh` → **无** `Error saving items`
3. 连续刷新 5 个条目，`no such tokenizer` 计数保持 **0**
4. 搜索「杜比」仍能命中 item 424（确认没有回归）

**风险**：低。虚方法 patch 是 Harmony 的常规用法；额外成本是每次连接创建多一次 `LoadTokenizerExtension` 调用（内部有 probe，已加载则立即返回）。

**回退**：保留原 `BaseSqliteRepository` 的 patch，新 patch 失败时自动降级到旧行为。

## 二、P1：HTTP/strm ISO 全链路（唯一大工作量）

> v8 的 `bluray:"{0}"` 路线**已实测否定**（`IsoMounter.cs:26-27`：bluray 协议在文件路径/挂载盘/HTTP 上均失败），必须换路。

| 步 | 内容 | 落点 |

| 项 | 理由 |
|---|---|
| 全量改 DI / 引 Autofac | 生命周期与 Emby 冲突，风险远大于收益 |

## 八、附：本轮诊断踩到的坑（供后续复用）

| 坑 | 结论 |
|---|---|
| `Logger.Debug` 看不到 | Emby `embyserver.txt` 只收 Info 及以上；**诊断埋点必须用 `Logger.Info`** |
| `DebugMode` 设了不生效 | 它是**一次性开关**：`Plugin.cs:194-197` 读到配置里的 `true` 就置内存 `DebugMode=true`，并**立刻把配置写回 false**。改配置只能生效**一次**启动 |
| 部署到错实例 | csproj 默认值曾是旧的 `D:\Downloads\embyserver`（4.9.1）；已改为 4.10.1.0 |
| git push 失败 | 环境代理对 GitHub 返回 502，直连 fetch 通但 push 超时；本地领先 2 个提交，网络恢复后重试 |
| 反编译定位 | `ilspycmd -t <全限定类型名> <dll>`；`BaseSqliteRepository` 在 **`Emby.Sqlite.dll`**，不在 `Emby.Server.Implementations.dll` |
