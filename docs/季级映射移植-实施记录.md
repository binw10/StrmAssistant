# 季级豆瓣匹配（季映射表）移植与实施记录

**日期**：2026-10-17
**目标**：解决剧集「第 N 季」条目豆瓣匹配 100% 失败的问题（日志 `No douban match for: 第 1 季` ×20）。
**参考**：PRO `BuildDoubanCacheTask.UpdateSeasonMap` + `Dto/Douban/DoubanSeasonsResponse`。

---

## 一、根因（实测确认）

豆瓣 `movie.douban.com/j/subject_suggest` 返回的 `type` 字段**把剧集与季都标成 `movie`**，而非 `tv`：

```
Q: 庆余年 第一季   → id=25853071 type=movie title=庆余年 第一季 year=2019
Q: 庆余年 第2季    → id=34937650 type=movie title=庆余年 第二季 year=2024
Q: 天才，女友 第1季 → id=28427782 type=movie title=我的天才女友 第一季 year=2018
```

而原实现 `SearchByTitleAsync` 用 `s.type == suggestType` 严格过滤（季条目传 `"tv"`），**候选被整批丢弃** → 无论标题多准都返回 null。第三策略（按剧名搜后筛「季」字）同样带 `type == suggestType` 条件，一并失效。

> 结论：季匹配失败**不是**缺少季列表接口，而是类型过滤把正确候选全干掉了。标题搜索本身完全可用。

## 二、实施内容（5 处改动，均在 `DoubanAssist.cs`）

### 1. 类型过滤放宽
新增 `IsVideoSuggestType(type)`：接受 `movie` / `tv`，排除 `person` / `game` / `book` 等。
`SearchByTitleAsync` 与季分支第三策略均改用该判断。

### 2. 季号强校验
新增 `BuildSeasonMarkers(n)`：`第N季` / `第二季`（中文序数）/ `Season N` / `Part N` / `第N部`。
季场景下候选标题**必须**包含其中之一，否则放弃（宁可无匹配，也不接受剧集主条目冒充季）。

### 3. 季级映射表（核心）
文件：`strmassistant_douban_seasons.json`
```json
{ "<剧集豆瓣ID>": { "1": { "SubjectId": "<季豆瓣ID>", "Updated": "<UTC>" } } }
```
- `TryGetSeasonSubject(seriesId, seasonNo)`：命中且未过期（7 天）才使用。
- `RememberSeason(seriesId, seasonNo, seasonId)`：搜索命中后回填并落盘；值未变时 1 小时内不重复写盘。
- 命中映射后若 `FetchSubjectAsync` 失败（条目下架/改 ID），自动回退搜索并覆盖映射。

### 4. 单季剧 S1 回退
豆瓣对单季剧**不建独立季条目**（剧集主条目即第一季页），搜索必然无果。
策略：仅 `seasonNumber == 1` 且父剧集已有豆瓣 ID 时，复用剧集 ID 作为季 ID；`S2+` 不回退。
日志：`Season S1 of {剧名} falls back to series subject {id}`。

### 5. 季条目纳入扫库填充
- `PopulateDoubanIdsAsync` 的 `IncludeItemTypes` 增加 `Season`。
- 修正两处传参：季条目此前传 `seasonNumber = null`，会走「剧集主条目」分支错配；现取 `(item as Season)?.IndexNumber`。
- `BuildCacheAsync` 同步修正。

## 三、实测结果（本机 Emby 4.10.1.0）

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 季条目匹配 | 0 / 8 | **7 / 8** |
| Populate Summary | `matched=0 noMatch=9` | `matched=7`（首轮）/ `matched=5`（二轮含 S1 回退） |
| 映射表 | 无 | 6 条剧集映射落盘 |

明细：
- 189「重器 S1」→ 25762332（大国重器 第一季，**源站暂无评分** rating=0，故无评分写入，属正常）
- 226「天才，女友 S1」→ 28427782（我的天才女友 第一季）→ **9.4 分，Applied=true**
- 27「余红旧事 S1」→ 37560173 → **7.8 分，Applied=true**
- 90/116/141/172 → 各自剧集主条目（S1 回退，其中夫妻的博弈源站暂无评分）
- 未匹配 1 个：series 5「中头奖还是要上班」本身无豆瓣 ID（剧集级匹配失败，非季映射问题）

## 四、遗留与后续

1. **季搜索未做年份校验**：季分支调 `SearchByTitleAsync(query, null, ...)`，同名片可能误配。可传「剧集首播年 + (N-1)」作为期望年份（±1）。风险低（季号标记已是强约束），列为可选优化。
2. **剧集级误配会传递到季**：如「重器」匹配到「大国重器 第一季」。季映射继承剧集 ID，若剧集本身错配，季也错。属标题模糊匹配的既有问题，与本次改造无关。
3. **PRO 的季列表接口未移植**：PRO 的 `DoubanSeasonsResponse`（`is_released`/`is_show` 等）疑似来自 rexxar `/v2/tv/{id}/seasons`，实测对单季返回 `[]`、对聚合 ID 未验证成功。当前基于 suggest + 季号校验 + 映射表已达成同等效果，暂不引入该接口。

## 五、补充修复：季匹配标题主体校验（同日）

**问题**：季搜索只校验「标题含季号」，不校验剧名主体。实测 `suggest("重器 第1季")` 只返回「大国重器 第一季」(2013)，被误认为本剧的季，导致 item 189 的豆瓣 ID 被写成 25762332（错），且源站无评分。

**根因**：剧集级匹配是正确的（`suggest("重器")` → id=36554071 title=重器 year=2026），错误只发生在季搜索；且季分支调 `SearchByTitleAsync` 时 year 传 `null`，年份校验完全没生效。

**修复**：
1. 新增 `NormalizeTitle`：去掉季/部标记（第N季/第N部/Season N/Part N/S1）、空白与中英文标点。
2. `SearchByTitleAsync` 增加 `expectedSeriesTitle` 参数：季候选须同时满足「含目标季号」+「归一化主体 == 归一化剧名」。
3. 第三策略（按剧名搜筛季标记）同样加主体校验。
4. 被拒后自然走 S1 回退（单季剧回退剧集 ID，结果正确）。

**实测**：
```
Season 1 of 重器: no candidate with matching title body (rejected unrelated titles)
Season map updated: series 36554071 S1 -> 36554071
Season S1 of 重器 falls back to series subject 36554071
item 189 → Douban 36554071，CommunityRating 7.3（修复前：25762332，无评分）
```

其他季未受影响：226→9.4、27→7.8、116→7.3、172→7.2。
