## 一、A 档：确定是 bug，可直接修

### A1　`LiveTvDirectRedirect` 的 `async void` Postfix → 竞态

**文件**：`StrmAssistant/Mod/LiveTvDirectRedirect.cs:98-121`

**现状代码**：

```csharp
[HarmonyPostfix]
private static async void GetChannelMediaSourcesPostfix(Task<List<MediaSourceInfo>> __result)
{
    if (!IsEnabled || __result == null) return;

    try
    {
        foreach (var mediaSource in await __result)     // ← 第一个 await 立刻返回
        {
            mediaSource.RequiresOpening = false;
            mediaSource.RequiresClosing = false;
            mediaSource.OpenToken = null;
            mediaSource.IsRemote = true;
            mediaSource.Protocol = MediaProtocol.Http;
            mediaSource.SupportsDirectPlay = true;
            mediaSource.SupportsDirectStream = true;
            mediaSource.SupportsTranscoding = false;
        }
    }
    catch (Exception e)
    {
        Plugin.Instance.Logger.Debug($"LiveTvDirectRedirect: 处理 MediaSource 失败 - {e.Message}");
    }
}
```

**为什么是 bug**：

1. `async void` 在 `await __result` 处**立即把控制权交回 Harmony**，Postfix 方法本身"返回"了
2. Harmony 把**原始 Task** 交给 `LiveTvManager.GetChannelMediaSources` 的调用方
3. 调用方 `await` 这个 Task 拿到 `List<MediaSourceInfo>` 后**立刻开始生成播放地址**（读 `SupportsDirectPlay` / `RequiresOpening` / `OpenToken`）
4. 而此时 Postfix 的 `foreach` 可能**还没跑到**（要等 `__result` 完成 + 线程池调度）
5. → 字段改没改**取决于调度顺序**

**症状**：Live TV 直链时好时坏；偶发仍走转码、仍带 OpenToken。而且是"偶发"，最难排查。

**修法**（换包：把修改逻辑包成新 Task 交回调用方，调用方 `await` 到的一定是改过的 List）：

```csharp
[HarmonyPostfix]
private static void GetChannelMediaSourcesPostfix(ref Task<List<MediaSourceInfo>> __result)
{
    if (!IsEnabled || __result == null) return;

    __result = MarkDirectPlayableAsync(__result);
}

private static async Task<List<MediaSourceInfo>> MarkDirectPlayableAsync(Task<List<MediaSourceInfo>> task)
{
    var sources = await task.ConfigureAwait(false);

    if (sources != null)
    {
        foreach (var mediaSource in sources)
        {
            mediaSource.RequiresOpening = false;
            mediaSource.RequiresClosing = false;
            mediaSource.OpenToken = null;
            mediaSource.IsRemote = true;
            mediaSource.Protocol = MediaProtocol.Http;
            mediaSource.SupportsDirectPlay = true;
            mediaSource.SupportsDirectStream = true;
            mediaSource.SupportsTranscoding = false;
        }
    }

    return sources;   // 关键：返回同一个 List 实例，调用方拿到的是改过的
}
```

**要点**：
- 参数从 `Task<...> __result` 改成 `ref Task<...> __result`（Harmony 支持 `ref` 写回）
- 方法签名从 `async void` 改成 `void`（不再需要 async）
- 异常处理保留在 `MarkDirectPlayableAsync` 内，用 `try/catch` 包住 `await` 与 `foreach`
- `Prepare()` 里的 `PatchUnpatch(..., postfix: nameof(GetChannelMediaSourcesPostfix))` **不用改**

**验收**：
1. `dotnet build -c Release` 0 警告
2. Emby 重启后日志出现 `LiveTvDirectRedirect: LiveTV 直链目标方法已就绪`，补丁数不变
3. Live TV 频道页连点 10 次播放，每次播放信息里都是 `DirectPlay`（改前应能复现"偶尔转码"）

**风险**：低。改动只涉及一个 Postfix 的签名与实现，不触碰补丁注册逻辑。

## 二、B 档：结构性问题，需先选路线

### B1　`ExclusiveExtract` 每次探测都**同步挂载** strm 目标（最严重）

**文件**：`StrmAssistant/Mod/ExclusiveExtract.cs:182-202`

```csharp
[HarmonyPrefix]
private static bool GetInputArgumentPrefix(ref string input, MediaProtocol protocol, ref string __result)
{
    if (protocol == MediaProtocol.Http) { ... return false; }

    if (LibraryApi.IsFileShortcut(input))          // .strm 判断
    {
        var inputPath = input;
        var mountPath = Task.Run(async () => await Plugin.LibraryApi.GetStrmMountPath(inputPath)).Result;
        if (!string.IsNullOrEmpty(mountPath)) input = mountPath;
    }
    return true;
}
```

**追到底**：`GetStrmMountPath` → `InvokeMountAsync`（`LibraryApi.cs:1080`）→ **直接调 `IMediaMountManager.Mount(...)`，全程没有缓存**。

**影响**：
- `GetInputArgumentPrefix` 是构造 ffprobe/ffmpeg 命令行的 Prefix，**每次探测 / 每次截图都会走**
- 对一个 `.strm` 库来说 = **每个条目每次探测都做一次真实挂载**
- 而且是**同步阻塞**（`.Result`），把挂载的网络/磁盘等待直接压在探测线程上
- 叠加 `MaxConcurrentCount` 并发时，线程池占用翻倍

**三个路线**：

| 路线 | 做法 | 改动量 | 收益 | 风险 |
|---|---|---|---|---|
| **B1-a（推荐）** | `GetStrmMountPath` 加结果缓存：`ConcurrentDictionary<string, string>`，按 strm 路径缓存；挂载释放/`Unmount` 时失效 | ~30 行 | **直接消除重复挂载**（同一 strm 只挂一次） | 低（缓存失效点要接对） |
| **B1-b** | 探测流程里提前 `await` 解析并写缓存，Prefix 只读缓存（纯同步、零阻塞） | ~60 行，要改探测调用链 | 最优（彻底不阻塞） | 中（要接对生命周期） |
| **B1-c** | 保留 `.Result` 但加超时：`Task.WhenAny(task, Task.Delay(5000))`，超时则不改写 `input`（回退原 strm 路径） | ~10 行 | 消除"无限卡住" | 低 |

**推荐组合：B1-a + B1-c**（先缓存消除重复，再加超时兜底）。两步互不冲突，可以先上 B1-a 观察效果，不够再补 B1-c。

**先量化的办法**：在 `GetStrmMountPath` 里加一行计时日志（`Stopwatch` + `Logger.Debug`），跑一次「刷新 50 个 strm 条目」，看挂载耗时占比。**如果单次挂载 < 5ms 且命中率高，B1-a 就够了；如果经常上百 ms，直接上 B1-b。**

### B3　`OptimizeMovieDbEpisodeScraping` 的 2 处 `.Result`

**文件**：`StrmAssistant/Mod/OptimizeMovieDbEpisodeScraping.cs:78` 和 `:114`

```csharp
var outcome = Task.Run(() => GetEpisodeMetadataFromSeasonAsync(options, cancellationToken), cancellationToken)
    .Result;

if (outcome.Result != null) { __result = Task.FromResult(outcome.Result); return false; }
if (outcome.SuppressFallback) { __result = Task.FromResult(...); return false; }
return true;   // ← Passthrough：放行原方法
```

**关键约束**：`Passthrough` 分支必须 `return true`（让原方法跑），而 `return false` 就必须给出 `__result`。**这个三态决策必须同步**——一旦 `return false` 就无法回头放行原方法。

所以**不能**简单改成 `__result = AsyncMethod(); return false;`，否则 Passthrough 语义丢失（会变成"永远短路且结果为 null"）。

**可行路线**：

| 路线 | 做法 | 评价 |
|---|---|---|
| **B3-a（推荐）** | 这个功能的核心就是「按季拉一次、服务全季」→ **第一集付一次网络 RTT，其余命中缓存**。加缓存预热 + 超时兜底即可 | 收益/成本最优 |
| **B3-b** | 改成 Postfix：放行原方法，再用季数据**替换**结果 | 丢失"减少请求"的初衷（原方法仍会请求），**不建议** |
| **B3-c** | 保持现状 | 可接受（有缓存） |

**推荐：B3-c 保持现状 + 加超时兜底**（`Task.WhenAny(task, Task.Delay(30_000))`，超时则 `return true` 放行原方法）。这样最坏情况退化成"没有优化"，而不是"卡死"。

## 四、D 档：另外发现的两个小问题（顺手可修）

### D1　`ClearTagline` 等 9 处 `ContinueWith` 会吞异常

**文件**：`StrmAssistant/Mod/ClearTagline.cs:61-62`、`:73-74`（同模式）

```csharp
__result = __result.ContinueWith(t =>
{
    if (t.Status == TaskStatus.RanToCompletion) ClearTaglines(t.Result);
    return t.Result;
});
```

**问题**：`ContinueWith` **不传播原 Task 的异常状态**——若原 Task Faulted，`t.Result` 会抛，但异常落在**新 Task** 上；且 `ContinueWith` 默认不继承 `TaskScheduler.Current`，与 `await` 语义不同。若外层不读新 Task 的异常，会变成 `UnobservedTaskException`（静默）。

**修法**（同 A1 的换包思路）：

```csharp
private static async Task<MetadataResult<Movie>> ClearTaglinesAsync(Task<MetadataResult<Movie>> task)
{
    var result = await task.ConfigureAwait(false);
    if (result != null) ClearTaglines(result);
    return result;
}
```

**成本**：9 处，约 30 分钟。

### D2　`LiveTvDirectRedirect` 的 catch 只记 `Debug`

```csharp
catch (Exception e) { Plugin.Instance.Logger.Debug($"... - {e.Message}"); }
```

如果 A1 修好后这里出问题，**线上完全看不见**。建议改成 `Warn` + `e.ToString()`（该路径低频，不会刷屏）。
